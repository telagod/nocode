Four invariants 四条不变量

The whole product is these four. Everything else is consequence. 整个产品就这四条。其余一切都是推论。

01

Skill is first-class

技能一等公民

Markdown files in .nocode/skills/ are loaded into prompt assembly with the same priority as CLAUDE.md. The model sees the index before it acts. Bodies materialize lazily.

.nocode/skills/ 下的 markdown 文件与 CLAUDE.md 同级注入 prompt。模型在动作之前就看到全部索引。skill 正文按需加载。

02

11 atomic tools

11 个原子工具

One job per tool, no overlap. The default registry is fixed and asserted by an integration test — no quiet sprawl. Everything else is opt-in.

一工具一职，零重叠。默认注册表由集成测试锁死 —— 不会悄悄膨胀。其余工具按需启用。

03

Three explainable gates

三道可解释门禁

Schema → Policy → Hooks. Every refusal carries a structured why-trail: Denied [<gate>: <reason>]. No silent denies, no opaque "Permission denied".

Schema → Policy → Hooks。每次拒绝都带结构化的 why-trail：Denied [<门>: <原因>]。零静默拒绝，零含糊"权限不足"。

04

Fractal sub-agents

分形子 agent

An Agent spawn runs the same harness as its parent — same registry, same skill index, same permission mode. Recursion inherits both capability and constraint.

Agent 派生出来的子 agent 运行同一份 harness —— 同样的工具表、技能索引、权限模式。递归同时继承能力和约束。

Configuration 配置

One TOML file. Edit it by hand. Run nocode init once for a commented template. 一个 TOML 文件，自己手编。nocode init 一键生成带注释的模板。 

# ~/.nocode/config.toml
default_provider = "subfox"
model = "gpt-5.5"
permission_mode = "ask"

[providers.subfox]
base_url     = "https://sub.foxnio.com/v1"
wire_api     = "openai-responses"     # anthropic | openai-responses | openai-chat | google
api_key_env  = "OPENAI_API_KEY"        # env var holding the key
default_model = "gpt-5.5"

[providers.local-vllm]
base_url     = "http://localhost:8000/v1"
wire_api     = "openai-chat"
api_key_env  = "VLLM_API_KEY"

[profiles.work]
provider = "subfox"

[profiles.home]
provider = "local-vllm"
permission_mode = "auto"

Observe — questions, not dashboards 观察 —— 提问，而非仪表盘

Inspired by antcode's observer discipline: each subcommand answers one specific question. No monolithic UI. 借鉴 antcode 的观察哲学： 每个子命令只回答一个具体问题，不堆叠仪表盘。

nocode insight 7-day summary: sessions, tool calls, denials 7 天总览：会话、工具调用、拒绝次数
nocode insight where File-first: where is the active state living? 状态在哪：当前 sqlite 卷的真实路径
nocode insight tools Tool-call frequency + error counts 工具调用频率 + 错误计数

nocode insight cost Token usage by provider/model 按 provider/model 统计 token 消耗
nocode config list Print current config (or --json) 打印当前配置（或 --json）

Why "no code" 为什么叫 "no code"

The name is a joke that became a discipline. Most agent harnesses add code on every release — new providers, new tools, new gates, new wizards. Each addition is a future tax: more lines to debug, more edges to forget, more docs to keep in sync.

这名字本是个玩笑，后来变成了纪律。多数 agent harness 每发一次版就加代码 —— 新 provider、新工具、新门禁、新向导。每次添加都是未来的税：更多行要 debug、 更多边角要遗忘、更多文档要同步。

nocode tries the opposite. Adding a feature should shrink the next adjacent feature more often than it grows it. Skill-as-first-class let tool/skill.rs drop ~70 lines. The PolicyEngine let tool/executor.rs drop ~145. Removing the login wizard let the binary drop 1128.

nocode 反其道而行。加一个特性，应该让相邻特性瘦身的次数多于膨胀的次数。 把 skill 升格为一等公民让 tool/skill.rs 减了约 70 行； 引入 PolicyEngine 让 tool/executor.rs 减了 145 行； 删除 login 向导让二进制减了 1128 行。

The harness is the product. Tools and gates are means.

harness 才是产品本身。工具和门禁只是手段。
